# ENTIP database contract (schema version 0001)

This folder is what pillars 1 to 4 code against. It is generated by `entip-db export-schema db/schema`.

- `0001_ontology.sql`: the PostgreSQL + PostGIS schema (tables, checks, triggers, the `patient_row` view).
- `schema.json`: the same, machine-readable: every table, column, type, key and reference, plus the rules.
- `openapi.json`: the HTTP API.

## Objects

```
patient (study_id)
 ├─ genomic_finding      marker, kind, result, detail, value, method   (from an assay or a report;
 │                       kind includes copy_number, e.g. marker chr7_chr10, result "+7/-10")
 └─ specimen             kind, site, day_offset
     ├─ assay            bulk genomics on the specimen (panel, wgs, methylation_array, ...)
     └─ block
         └─ section      stain, thickness_um, serial_index
             ├─ scan     mpp, width_px, height_px, uri, tile_source, link_code
             │   ├─ cell         x_um, y_um, outline, source, model_id
             │   ├─ region       polygon / tile / hotspot, with a label (necrosis, tumour, ...)
             │   ├─ annotation   feature, label, geometry, locked, retracted
             │   └─ prediction   model_id, target, score
             └─ assay    spatial (visium, xenium, slide_tags, anndata)
                 └─ spatial_object   spot / nucleus / bin, placed through a transform
transform   src_frame -> dst_frame, matrix, rmse_um (required), loo_rmse_um, max_err_um
feature     name, level (cell | tile | region | spot), positives_only
model       feature, kind, encoder, status (draft | challenger | champion | rejected | retired), licence
action / change   the log: every write, who made it, before and after
```

`patient_row` (`GET /patients`) gives one row per patient: clinical fields, `molecular` (latest result per
marker, e.g. `{"IDH": "mutant", "1p19q": "codeleted"}`), `molecular_detail`, counts, `scan_ids`, `stains`,
`assay_ids`, `assay_kinds`.

## Rules the database enforces

- **No identifiers.** Patients are known only by `study_id`. Keys such as `chi`, `nhs_number`, `dob`,
  `patient_name`, `accession`, `postcode` are refused anywhere in a payload, and a bare 10-digit number in an id
  is refused. The CHI-to-study_id key stays in pillar 1's NHS-side store. No calendar dates: use day offsets.
- **Micrometres in a named frame.** `scan:<scan_id>` (level 0, origin top-left), `assay:<assay_id>`,
  `section:<section_id>`. Cells, regions and annotations must be in their own scan's frame. A spatial object in
  any frame other than its assay's must name the `transform_id` that put it there, and a transform must carry
  `rmse_um`.
- **Provenance on every object:** `{"kind": "person" | "model" | "program", "actor": "...", "version": "..."}`.
  A record without one takes the action's.
- **Every write is an action.** Tables refuse INSERT / UPDATE / DELETE unless the transaction began an action;
  triggers copy each change (before and after) into `change`. `action` and `change` cannot be updated, deleted
  or truncated. Annotations are retracted, not deleted. Only cells, regions, predictions and spatial objects can
  be deleted, to replace a run.
- **One champion per feature** (unique index).

## Writing: `POST /actions`

```json
{
  "verb": "create",
  "object_type": "annotation",
  "provenance": {"kind": "person", "actor": "person:trainee-01"},
  "records": [{"annotation_id": "ann_0001", "scan_id": "SCN-0001-A1-01", "feature": "mitotic_figure",
               "label": "positive", "geometry": {"type": "point", "x_um": 1520.0, "y_um": 880.5},
               "target_type": "cell", "target_id": "SCN-0001-A1-01:c000123"}],
  "detail": {}
}
```

- `verb`: `create`, `upsert` (idempotent re-registration), `update` (key fields + changed fields), `retract`
  (annotations), `delete` (bulk tables; `{"scan_id": ...}` clears a scan's cells or regions,
  `{"model_id": ..., "scan_id": ...}` clears a model's predictions on a scan), `promote` (models:
  `{"model_id", "demote_to"?}` makes it its feature's champion and retires the old one in the same action).
  Any other lower-case verb (`fork_slide`, `train`) records an event with `detail` and no records.
- `object_type` may be left out if every record carries `"type"` (`"Patient"`, `"SpatialObject"`, ...): one
  action can then register a whole patient chain, in order.
- `action_id` is optional; send your own to make retries safe.
- Geometry: `{"type": "point", "x_um", "y_um"}`, `{"type": "polygon", "points_um": [[x, y], ...]}`,
  `{"type": "box", "x_um", "y_um", "w_um", "h_um"}`, or GeoJSON in micrometres. Regions also take
  `x_um, y_um, w_um, h_um` directly. Cells take `outline_um` (a ring).
- Errors come back as HTTP 422 with a plain message; nothing is written.

## Reading

| Endpoint | Returns |
|---|---|
| `GET /patients?cohort=&diagnosis=&marker.IDH=mutant` | patient rows |
| `GET /patients/{study_id}` | row + `specimens[] > blocks[] > sections[] > scans[]`, `assays[]` on sections and specimens, `genomic_findings[]`, `transforms[]` |
| `GET /patients/{study_id}/actions` | that patient's action log, with changes |
| `GET /scans/{scan_id}` | one scan (with `stain`, `width_um`, `height_um`, `study_id`, and `patient`: diagnosis, grade, markers) |
| `GET /scans/{scan_id}/cells?bbox=x0,y0,x1,y1&model_id=&after=&limit=` | cells, optionally with a model's `score` |
| `GET /annotations?feature=&label=&locked=&include_retracted=&study_id=&since=` | annotations across all scans |
| `GET /scans/{scan_id}/regions?kind=&label=`, `/annotations?feature=`, `/predictions?model_id=&order=uncertain` | slide objects; `order=uncertain` sorts by \|score − 0.5\| |
| `GET /assays/{assay_id}`, `/assays/{assay_id}/objects?bbox=` | assay and its spots / nuclei |
| `GET /transforms?frame=scan:...` | transforms into or out of a frame |
| `GET /features`, `GET /models?feature=&status=` | features, models |
| `GET /objects/{type}/{id}`, `/objects/{type}/{id}/history` | any object and its history |
| `GET /actions?since=&verb=`, `GET /actions/{id}` | the log |
| `GET /schema`, `GET /health` | this contract live; versions |

## Mapping from the pillars' stand-ins

**Pillar 1 (fork, `registry.py`).** The outbox objects load as one mixed `upsert` action (`object_type` null,
each record keeps its `"type"`). Changes: Scan `width`/`height` become `width_px`/`height_px`;
`source_format` becomes `format`; `levels` goes in `meta`; drop `frame` (it is always `scan:<scan_id>`). The
action's `kind` becomes `verb`, `inputs`/`outputs` go in `detail`. `mpp` is required: a slide with no pixel
size cannot place anything in micrometres. Pass the actor as provenance `{"kind": "program", "actor": ...,
"tool": "entip-fork", "tool_version": ...}`.

**Pillar 2 (training, `ontology.py`).** Scan `width_um`/`height_um` are computed from pixels × mpp. Feature,
Cell, Region and Annotation fields match, with: Region `x_um, y_um, w_um, h_um` accepted as is; Annotation
`author` and Feature `created_by` and Model `trained_by` become `provenance`; Model `artifact` becomes `uri`,
`parent` becomes `parent_id`. Scores go in `prediction` (one row per model and target), which feeds the review
queue (`/predictions?order=uncertain`). Retract annotations with verb `retract`.

**Pillar 3 (spatial, `ontology.py`).** Transform and SpatialObject fields match one to one (`provenance` with
`kind: "model"` is fine). Assay `source_path` becomes `uri`, `source_sha256` becomes `sha256`; spatial assays
need `section_id`. Load spots with one `create` action per assay (one log row, not one per spot).

**Pillar 4 (GUI).** Your assumed shapes hold, with these differences: `sex` is `female | male | other |
unknown`; counts also include `n_specimens`, `n_blocks`, `n_sections`; scans carry `stain` and `tile_source`;
cells carry `source` and `model_id` (provenance of the run) rather than a provenance object; annotations are
`POST /actions` with the body above (actor and time come from `provenance` and the server clock).
